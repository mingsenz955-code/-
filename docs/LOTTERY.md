# 基础抽奖 v0.10

当前是**可操作的离线基础池实现**，不是已证明与服务器概率、数量和画面逐项一致的完整复刻。活动抽奖、后期翻牌、免费次数、保底、票券获取仍未完成。

## 直接确认的客户端规则

来源`ui/DragonRandPanel.lua`，基线Android 2.9.35 / 资源202402271124：

- 普通：单次30、十连300，对应CommonrandMoney。
- 高级：单次80、十连800，对应AdvancerandMoney。
- 优先扣对应抽奖币，不足部分按1:1用魔晶补齐；其他档位抽奖币不能混用。
- 待领取栏最多30格，十连需10个空位。
- 资源留在待领取栏，领取后才入账；幼龙单独选择栖息地安置。
- `RandDragonPanel.rear`生成Lv1龙，再请求放入栖息地；因此当前抽中龙安置后直接Lv1入住，不另外虚构孵化计时。
- 原普通展示龙：1055/1001/1060/1010/1059/1004/1008/1066。原高级展示龙：1073/1041/1003/1013/1049/1023/1065/1032。展示8条不等于奖池只有8条。

代码、表哈希及规则清单在`assets/original/data/lottery-provenance.json`；静态导出脚本`scripts/export-lottery.py`保留43条原始数组。普通15行，高级28行，包含金币/食物/龙。

## 明确的离线推断

原`LibDragonRandInfo.lua`把nummin和nummax都映射第5列，把weight映射第6列。原`DragonRandLibrary.getRandomInfo`是界面转动时随机选择装饰项，不是服务器实际开奖；不能把它的等概率展示随机函数当真实抽中概率。

原表第7列在每档递增至100000。当前`offline-cumulative-v1`把这一列解释为累计阈值、第5/6列解释为整数数量上下限。这是显式离线解释，**尚未证明服务器实际采用相同概率/数量算法**。每条持久奖励记录携带policy和sourceRow，界面也显示未核实状态，不声称原概率已复刻。

抽取时结果立即确定并持久化；浏览、关闭、重启不重新抽取。仅在保存成功后替换界面状态。抽数/档位/资源/奖励结构严格验证，异常随机值和中途失败不修改原状态。

## 存档与试玩

- 存档升级v5，兼容v1–v4，新增`lottery`（两类币、抽数、待领取奖励）。旧档迁移不送抽奖币或魔晶，旧龙/资源/农场/繁殖/孵化保持。
- 领奖不会复制奖励；满巢、元素不匹配或未完工均保留幼龙。奖励实例ID与牧场实例共享唯一性校验。
- 正式档仍在`%APPDATA%/YulongRanch/saves/ranch-v1.json`。v5阻止旧程序覆盖；旧有效档按既有备份机制保留。
- `抽奖试玩.cmd`使用`%APPDATA%/YulongRanchLotteryDemo`独立演示档，首次提供1000测试魔晶、300普通币、800高级币；只供试玩。重复启动读取该演示档，不反复赠送。正式牧场不加资源。
